# ADR-001: Dependency-Free Local Concept
Status: Accepted for concept stage only
Date: 2026-10-14
Decider: CWU implementation within owner-authorized local concept scope

## Context
A distinctive interactive concept must be reviewable without clinic credentials, patient information, hosting spend or external media rights. Scale and production hosting are not yet requirements.

## Decision
Use semantic HTML, shared CSS tokens, a small local JavaScript state map and original inline SVG illustration. No API, database, cookies, storage, third-party scripts, form endpoint or appointment integration. Browser button event selects one of four allowlisted editorial records and updates text/graphic attributes. Facts and creative rationale live in docs; workflow profile maps gates.

## Options Considered
| Option | Complexity / Cost | Advantages | Tradeoffs |
| --- | --- | --- | --- |
| Static HTML/CSS/JS | Low / no service cost | Portable, quick inspection, graceful no-JS baseline, tiny delivery | Manual content maintenance if many routes added |
| React/static framework | Medium / potentially no hosting cost | Shared components and expansion tooling | Unnecessary dependency/build surface for one concept |
| CMS or existing Squarespace changes | Higher / ownership and account dependencies | Content editor and possible existing hosting | Outside current authority; risks live changes |

## Consequences
Local concept is easy to review and discard/revise. It is not an operational clinic system. Revisit stack only after approved route inventory, content ownership, hosting and maintenance workflow. No speculative load estimates needed for a local page.

## Acceptance
All four states work by pointer/keyboard, no-JS baseline remains readable, contact accessible, no network submissions, no horizontal overflow at 320/390/768/1440, shared colophon and link checks pass. Production scheduling requires separate privacy/vendor/delivery design and approval.
